# 13 — Tier 1 analytical dam-break benchmark

## Goal

Close the Tier 1 gap in `../../architecture/validation-plan.md` §1 /
Go/No-Go criterion #1: independent closed-form correctness validation of
the solver, not just cross-backend agreement. Two cases:

- **Stoker wet-bed dam-break** — exact solution with a bore (shock),
  rarefaction fan, and constant middle state. Validates shock speed and
  the scheme's shock-capturing accuracy.
- **Ritter dry-bed dam-break** — exact solution with a moving wet/dry
  front. This is the wet-dry-boundary correctness test: front position,
  no negative depths, and depth error across the fan are gated.

Both run on a synthetic flat-bed rectangular channel mesh generated by
the harness itself (parquet with explicit `z_mean=0` — `build_geometry`
substitutes a sinusoidal bed when the mesh file carries no bed
attribute, which would invalidate the flat-bed analytical solutions).
No external data files.

## Harness

`deceris/inundation/bench/dambreak.py`, run via `just benchmark-dambreak`.
Analytical solutions + channel-mesh builder live in `bench/common.py`
with pure-NumPy unit tests (`tests/unit/test_bench_dambreak_analytical.py`)
covering region boundaries, the Ritter 4/9·h0 dam-site depth, the Stoker
rarefaction/shock matching condition, Rankine-Hugoniot residuals, and the
Stoker→Ritter limit.

Backends are configurable (`--backends`, CSV of `solver_impl` names).
Default is `gpu_resident_batch`, the one Vulkan reference that is correct
on both macOS/MoltenVK and CUDA/Linux (see results). On the GPU node add
`fixed_dt_batch_barrier` (the production reference) and
`cuda_graphs`/`cuda_streams`. Running the Vulkan reference through the
same gates distinguishes CUDA-port bugs from errors inherited from the
original scheme.

## Setup (defaults, all overridable)

| Parameter             | Value                                                           |
| --------------------- | --------------------------------------------------------------- |
| Channel               | 1000 m × 10 m, flat frictionless bed (`n = 1e-4`, solver floor) |
| Grid                  | 500 × 5 quads (dx = dy = 2 m)                                   |
| Dam position          | x = 500 m                                                       |
| Upstream depth        | 10 m                                                            |
| Downstream depth      | 1 m (Stoker) / dry (Ritter)                                     |
| End time              | 20 s (waves stay clear of the reflective walls)                 |
| dt_max / cfl_interval | 0.02 s / 5                                                      |

## Gates (per validation-plan.md §1: documented, not implicit)

| Gate                             | Tolerance                                       | Justification                                                                                                                                                                                              |
| -------------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Depth L1 relative error vs exact | ≤ 0.05                                          | First-order FV schemes at dx/L = 1/500 typically reach 1–3 % on this case (Toro, _Shock-Capturing Methods for Free-Surface Shallow Flows_, ch. 10); 5 % leaves regression headroom                         |
| Ritter front position error      | ≤ 0.15 of analytical travel                     | Numerical wet front classically lags the dry-front tip (dry tolerance + first-order diffusion); measured ~12–13 % here, 15 % is the standard wetting/drying band (Liang & Marche 2009; Brufau et al. 2002) |
| Volume drift (zero-source run)   | ≤ 1e-5 relative                                 | float32 accumulation error only                                                                                                                                                                            |
| Negative depths                  | none                                            | Solver clamps; gate catches clamp regressions                                                                                                                                                              |
| Run-to-run reproducibility       | ≤ 1e-5 relative to peak depth (`--repeats ≥ 2`) | GPU `atomicAdd` flux scatter is not bit-reproducible (summation order varies per dispatch); healthy runs reproduce to ~4e-7                                                                                |

## Performance measurement

Per (case, backend): `--warmup` runs excluded, median wall seconds over
`--repeats`, steps/s and cell-steps/s. Timed runs default to a single
final snapshot so device→host downloads don't pollute timing. `--gif`
renders a **separate untimed** run into a depth-profile animation
(numerical vs analytical overlay); timed runs are never the frame source.
The gif frame count is snapped to the nearest power of two so
`t_end / frames` is exactly representable in float32 —
`gpu_resident_batch`'s device-side time advance stalls on
non-representable output intervals (e.g. 20 s / 60).

## Artifacts

`--output-dir` (default `.tmp/dambreak-bench/`): generated channel mesh,
`summary.json` (gates + per-run correctness/perf metrics), optional
`<case>-<backend>.gif`.
